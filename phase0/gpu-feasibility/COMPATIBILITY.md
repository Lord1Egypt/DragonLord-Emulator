## Android 16: documented integration path, no boot claim

The source reference remains AOSP `android-16.0.0_r4`, `aosp_cf_x86_64_only_phone`, Cuttlefish commit `4d368849922b04124e66b1aad48f93b3209f3c8d`, shared kernel default 6.12. The separately resolved [AOSP Gfxstream release commit](https://android.googlesource.com/platform/hardware/google/gfxstream/+/7e9d595b097b23f5fa5c114088245c819e29a9af) is **`7e9d595b097b23f5fa5c114088245c819e29a9af`**, different from the current experimental host `94240f81…`. That difference does not itself prove protocol incompatibility, but it makes exact host/guest protocol qualification necessary. No matching prebuilt artifact or full resolved manifest has been selected. Do not call the two source pins a working matched pair.

Its eventual device parameters must come from a successfully built/discovered device and tested guest, not a command presented here as working.

**Available:** source-level components and a specific BSP reference. **Requires engineering/qualification:** native renderer/FFI closure, ownership/lifetime/fence fixes, Windows presentation, exact protocol pairing and complete VM board/service mapping. **Unverified:** Android 16 boot, EGL/GLES/Vulkan correctness, UI/input behavior, physical GPU execution, performance and KernelSU.
