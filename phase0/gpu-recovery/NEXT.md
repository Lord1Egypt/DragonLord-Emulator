**NO-GO for guest-visible device integration now.** Tooling recovery can continue. Reopen the integration gate only against exact published revisions after the prerequisites below pass; do not start Android builds/full migration.

| Ticket | Dependency | Definition of done |
|---|---|---|
| R1 Valid independent tracing control | Appropriate Windows ETW access or validated equivalent | Same pinned Gfxstream workload on hardware/CPU; process/device/queue correlation, valid zero/absence interpretation, immutable raw trace provenance and explicit no-fallback assertions. Preserve current ETW access denial and invalid-counter failures. No driver/security/virtualization changes without authorization. |
| R2 Correct fence header upstream | Native ABI reproduction | Submit/review the one-field correction with original failing control; document ABI compatibility/version policy. Rebuild/test every consumer against the same header/types. No upstream contribution is submitted by this phase. |
| R3 QEMU-specific mapping retirement proof | Source audit; R2 for final ABI | Extract/use actual QEMU lifecycle code and prove no free/unmap while RCU/MemoryRegion/accelerator/GPU reader holds a reference. Test overflow/offset/access errors, duplicate map/unmap, timeout retention, allocation failure and reset/unrealize under pending callbacks. Sanitizers/stress and failure-injection evidence required. Reference lease tests alone do not satisfy this. |
| R4 Callback generation/teardown safety | R3 | Device/context generations, reject stale callbacks and context-ID reuse, drain/cancel main-loop work before freeing device/renderer. Real code tests for duplicate/out-of-order callbacks, concurrent reset and shutdown; no deadlock or UAF. |

No binary distribution before closure. |
| R6 Minimal host/FFI streaming proof | R1, R2, owned-memory design | One real guest-API stream into Gfxstream through pinned Rutabaga, bounded allocation/map/submit/readback/fence/destroy, explicit GPU handles/CRT ownership and negative/reset controls. | R7 Minimal QEMU device experiment | R1–R6 | Isolated Windows build with exact discovery/import metadata, QEMU device realization/capsets and a tiny diagnostic guest resource/fence round-trip; WHPX-only, no Android image. | R8 Android source pairing plan | R7 | Resolve complete existing Android 16 BSP/guest driver pins, negotiated host protocol/features/HAL/kernel interfaces and reference artifacts; execute separate approved reference boot before authoring images. KernelSU stays optional/unqualified. |
| R9 Native clean replay/CI extension | Portable tooling and lockfiles | Fresh short Windows workspace or dedicated physical runner builds exact pins and runs native ABI/memory units with immutable evidence. No requirement for software CI runners to pretend to have a physical GPU. |
| R10 Legacy build repair | Separately scoped legacy work | Preserve legacy/main; resolve actual Python `pwd` configure failure and subsequent dependency/source issues on a dedicated job. Modern QEMU evidence remains independent. |

After R7, reconsider the architectural verdict using runtime correctness, hardware proof, security and licensing closure. Performance work then uses the original benchmark definitions; test-suite wall times here are not emulator FPS or latency results.
