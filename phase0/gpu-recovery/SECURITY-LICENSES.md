# Security boundaries and dependency obligations

This checkpoint does not clear guest-memory integration or binary redistribution. Source audits identify risks; tests establish only their executed scope.

| Boundary | Required contract | Current evidence / unresolved risk |
|---|---|---|
| Guest descriptors → QEMU | Validate IDs, counts, size/offset arithmetic with subtraction checks, permissions, alignment and host-window bounds before any host dereference/map | No new guest device exposed. Reference range tests pass; actual QEMU blob offset/overlap/error behavior needs extracted-code tests. Never treat a guest integer as a host pointer/HANDLE. |
| Renderer memory → QEMU/WHPX | Allocation owner outlives every RCU/MemoryRegion/accelerator reader and GPU job | Pinned source explicitly notes pointer retirement risk. Standalone leases do not establish QEMU/WHPX safety. Integration remains blocked. |
| Foreign callbacks → main thread/device | Owned/generation-tagged device references; drained or cancelled pending work before teardown; no stale context-ID completion | Context-ID selection fix passes units, but scheduling uses a raw device pointer. Reset, context reuse and shutdown with pending asynchronous renderer callbacks remain unverified. |
| C ↔ Rust fence | Exact field widths, size, alignment, offsets and valid storage for callback duration | Original C header FAIL; copied uint8 header PASS for tested round-trips. All consumers must agree before deployment; no silent global header replacement. |
| HANDLE transfer | Borrow/duplicate/consume/export semantics explicit, full pointer width, invalid sentinels rejected, ownership closed once by origin | Actual OwnedDescriptor/core tests pass. GPU external memory/semaphore handles, cross-process policy and failure after live submit remain unverified. |
| C/C++/Rust CRT | Caller owns supplied buffers; opaque allocations destroyed through originating library; no cross-runtime free/realloc | Core DLL tests obey this contract. PE imports identify MSVC/UCRT dependencies. MinGW QEMU and MSVC Rust/ClangCL combined behavior has not been tested. |
| Loader/tool supply chain | Pinned hashes, official archives, isolated keyring and scoped DLL/environment selection | LLVM detached signature + hashes verified; Rust manifest checksum verified. Hardware module signatures/hashes captured. Browser SwiftShader is a local control only, not a redistributable dependency. Empty ICD override crash retained. |
| Windows tracing | Stop only the session started by this experiment; preserve permission failure; no changes to security/driver/virtualization | Named session start denied (0x5). Per-process GPU counters provide positive hardware data but invalid software data; no assumption of zero. |

Recommended retirement ordering: reject new submissions/maps and stale generations; remove guest-visible exposure transactionally; retire accelerator mappings; drain jobs/callbacks and QEMU readers on the appropriate threads; retain allocation/handle owners during any timeout; unmap/free/close last through the origin. A concrete QEMU implementation must establish the actual API/thread/RCU ordering, not merely copy the reference class.
